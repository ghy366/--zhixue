## 浏览器实测揪出「点发送没反应」的真正根因（用户核心痛点）
- 用 agent-browser 真实浏览器复现：登录 → 开 AI 面板 → 点发送 → 用户气泡根本不出现、`aiSend` 从未被调用。
- 根因：index.html 里 `app.js` 的 `<script>` 在第 322 行，而 AI 面板 HTML 在第 494 行之后。`bindAiChat` IIFE 在脚本加载时立即执行：`#ai-chat-btn`（243 行）已存在→切换按钮绑定成功；`#ai-chat-close`（500 行）还是 null → `addEventListener` 抛 TypeError → **发送按钮/Enter/快捷提问/关闭按钮的监听全部没绑上**。表现即"能打开面板能打字，点发送毫无反应"。
- 修复：bindAiChat 改为具名函数 + `DOMContentLoaded` 后执行，且每个元素判空再绑定（app.js 尾部）。
- 顺带修复：jsdelivr 云 SDK 从阻塞 `<script>` 改为 `aiLoadSdk()` 按需懒加载（CDN 不通时会白屏阻塞整页渲染，实测复现白屏）；版本号升 v=20261013b。
- 后端加双保险：AiService 主通道(Intern-AI)失败（实测该 key 高频调用会间歇性 401/402）自动回退 Pollinations 免费通道（ai.fallback-base-url），保证始终能聊。
- 浏览器最终验证 ✅：点发送按钮 → 用户气泡+Intern-AI 中文回复完整显示；快捷提问按钮也能发送。agent-browser 环境走代理较慢(14s)，用户本地浏览器约 2s。
- 教训：**给静态页加新 DOM 时，若其 JS 绑定在较早加载的脚本里，必须等 DOMContentLoaded**；排查此类问题直接用 agent-browser 真实浏览器 + `eval` 包装函数追踪，比读代码猜快得多。
