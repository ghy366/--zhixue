## 一、严重问题（建议优先修复）

### S1 ✅已验证　系统级写接口漏登记鉴权，任意学生可推进学期/改配置
- **位置**：`config/RoleInterceptor.java:196-211`（未命中规则→任意登录放行）+ `controller/SystemController.java:185` `/semester-advance`、`:196` `/teacher-max-courses`
- **问题**：规则表漏了这两个 POST 接口（只登记了 `/max-courses` 名字不同的旧接口）。`startsWith` 未命中后走 `matched == null return true`，任何登录学生都能推进学期偏移、释放名额、改教师上限。
- **修复**：规则表补 `POST /api/system/semester-advance` 和 `POST /api/system/teacher-max-courses` → ADMIN；根本方案是改默认策略为「未命中即拒绝」。

### S2 ✅已验证　教师专属规则被公开课程规则前缀吞并
- **位置**：`RoleInterceptor.java:54` `GET /api/courses → null`(公开) 在 `:150` `GET /api/courses/teacher/ → TEACHER_ADMIN` 之前
- **问题**：规则按声明顺序 `startsWith` 首条命中即 break，`/api/courses/teacher/123` 命中公开的 `/api/courses`，教师专属保护形同虚设，未登录即可拉教师名下课程。
- **修复**：把更具体规则前置，或把 `/api/courses` 改精确匹配。

### S3 ✅已验证　自动排班模式轮次门控卡死第 1 轮
- **位置**：`service/RoundScheduleService.java:141-147` + `roundProgress` 写入点仅 `CapacityService:64`(置0)、`SystemService:75`(手动关闭时)
- **问题**：自动模式 `syncOnce()` 只改 currentRound/roundOpen，从不推进 `roundProgress`，`unlocked = progress+1` 恒为 1；第 2 轮窗口到时被 `if (newRound > unlocked)` 强制拉回第 1 轮且不开放。自动排班永远卡在第 1 轮。
- **修复**：`syncOnce` 在检测到某轮窗口整体结束时推进 `roundProgress`。

### S4 ✅已验证　第三轮换课容量口径错误，可超卖
- **位置**：`service/EnrollmentService.java:1034`（swap）vs `:692`（enroll）
- **问题**：enroll 第三轮按「本学期跨轮 approved 数」判容量（注释明确记录了曾出现 5/4 超卖的坑），但 swap 第三轮只数本轮 `findByCourseIdAndRound`，漏改。容量 4、前两轮已录 4 人时，换课仍可放行 → 5/4。
- **修复**：swap 改用 `findByCourseIdAndSemesterNo` 同口径。

### S5 ✅已验证　手动结算接口结算后不关轮次、不推进进度
- **位置**：`controller/EnrollmentController.java:475-492` `/settle`
- **问题**：`settleRound` 只改 pending→approved/rejected，不改 roundOpen/roundProgress。管理员据此结算后 `roundUsable` 仍 true，学生可继续向已结算轮次报名并挂 pending，且下一轮仍锁定 → 悬挂数据无人结算。
- **修复**：结算成功后同步执行关闭语义，或禁止开放状态重复结算。

### S6 ✅已验证　Schedule.vue「加入意向单」调用不存在的接口却报成功
- **位置**：`frontend/src/views/Schedule.vue:894-910`
- **问题**：`fetch('/api/intents', POST)`，但后端 `IntentController` 只有 `/add /remove /clear /submit`，无根路径 POST → 必然 404/405。且 `fetch` 不检查 `resp.ok`/`success`，无条件 `ok++`，最后提示「已加入 N 门」。功能完全失效却误报成功。
- **修复**：改 `http.post('/intents/add', {courseId, points})`，按 success 统计。

### S7 ✅已验证　MyEnrollments 批量退课把报名 id 当课程 id
- **位置**：`frontend/src/views/MyEnrollments.vue:478-480,459,559`
- **问题**：列表 `id = enrollmentId`，勾选收集 `row.id`，却作为 `{courseIds}` 提交给 `dropBatch`（后端按 courseId 处理）。退课作用于错误课程或整批失败。（注：代理原报告误写为 UserMgr.vue，实际文件为 MyEnrollments.vue）
- **修复**：勾选/提交改用 `e.courseId`。

### S8 ✅已验证　教师可越权查看任意课程学生名单（含手机号）与成绩
- **位置**：`controller/EnrollmentController.java:427-436` `/course/{id}`、`controller/GradeController.java:43-76` `/course/{id}`
- **问题**：均无 `course.teacherId` 归属校验，任意教师可拉任意课程名单（courseEnrollments 还返回手机号）。对比同文件 `saveGrade` 有 teacherId 校验，属遗漏。
- **修复**：接收 token 解析教师身份校验归属，管理员放行。

### S9 ✅已验证　CSV 导出公式注入 / 会话永不过期（安全类）
- `service/DataService.java:28-34` CSV `esc()` 未处理 `= + - @` 开头字段，用户可控的姓名/课程名填 `=HYPERLINK(...)` 用 Excel 打开会执行。
- `util/SessionStore.java:9-22` token 无过期、无清理、无上限，内存泄漏 + token 泄露后永久有效。
- `controller/AuthController.java:276-280` 限流 IP 取可伪造的 X-Forwarded-For，撞库锁定可绕过。

## 四、各维度覆盖说明

- **鉴权**：Admin/Stats/Data/Logs 四类接口有 `* → ADMIN` 通配保护，未发现直接绕过；问题集中在「写接口漏登记」「前缀吞规则」「GET 变体漏登记」（S1/S2 + `GET /api/system/grade-reqs`、`GET /api/system/phase` 也未登记）。
- **并发**：选课主流程 enroll/drop/reselect/swap 采用「先锁学生行再按 ID 顺序锁课程行 + READ_COMMITTED」，死锁防范正确；settleRound 用配置行锁做全局互斥有效。问题在 startNewCycle(S3)、waitlist confirm(M2) 缺锁。
- **事务**：主要写操作均有 @Transactional；未发现缺注解导致的部分成功。
- **统计口径**：除零/空集合/数组越界均有防护；但满员率 `report()` 用 approved/cap、`liveAnalysis()` 用 applied/cap，同一指标两种算法，建议统一。
- **前端内存泄漏**：Rounds/Stats/Login/MainLayout 的定时器与监听均在卸载时清理；仅 GradSky3D(M6) 有问题。
- **未发现问题**：SQL 注入（全部 Spring Data JPA 方法名查询，无字符串拼接）、调度器结算幂等（行锁+单实例串行）、学生态接口越权（均以 token userId 为查询主体）。
